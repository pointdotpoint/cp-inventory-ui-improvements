# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

WardrobeTabs: a redesign of the Equipment-EX wardrobe screen for Cyberpunk 2077 (patch 2.5), written in redscript. The project covers the wardrobe UI only; the earlier inventory work (PreviewPoses, PreviewZoom, FastInventory snapshots, inventory prototypes, timing probes and research) was removed on 2026-10-25 and is in git history at commit `5f1dda9`. The game runs on Linux through Steam/Proton with redscript, Codeware, ArchiveXL, TweakXL, CET, Equipment-EX and Virtual Atelier installed. On 2026-10-25 every non-vanilla file was moved to `~/Games/cp2077-mods-removed-20261025/` (its README says how to restore) and only some mods came back.

Scripts are compiled by the game at launch. Native UI behaviour needs in-game verification by the user.

## Commands

```bash
tools/compile-check.sh        # compile every installed script + mod/ in a throwaway staging copy
tools/build_pack_index.py     # regenerate the known pack names (WardrobeTabsPackNames.reds) from the game's r6/tweaks
```

Run this before installing any `.reds` change. It uses the game's own `scc.exe` under Wine and writes nothing into the game folder. A compile error that reaches the game disables all script mods for that launch, so never install unchecked scripts.

Installing is a plain copy; the game recompiles on next launch:

```bash
GAME="$HOME/.local/share/Steam/steamapps/common/Cyberpunk 2077"
cp -r mod/r6/scripts/WardrobeTabs "$GAME/r6/scripts/"
cp mod/archive/pc/mod/WardrobeTabs.archive "$GAME/archive/pc/mod/"
```

`WardrobeTabs.archive` holds `wardrobe_tabs\gui\grid.inkwidget`, the card grids (library items `Root4`..`Root7`, one per column count, each with its own cell item `wardrobeCell4`..`wardrobeCell7`). Rebuild it from Equipment-EX's layout: extract and serialize `equipment_ex\gui\wardrobe.inkwidget` from `EquipmentEx.archive`, run `tools/build_wardrobe_grid.py <wardrobe.inkwidget.json> <grid.inkwidget.json>`, deserialize the output and pack it at `wardrobe_tabs/gui/grid.inkwidget`.

Where to look after a run:

- `$GAME/r6/logs/redscript_rCURRENT.log`: the game's own compile result.
- `$GAME/bin/x64/plugins/cyber_engine_tweaks/gamelog.log`: the mod's `WardrobeTabs` log lines.
- `~/.local/share/Steam/steamapps/compatdata/1091500/pfx/drive_c/users/steamuser/AppData/Local/REDEngine/ReportQueue/`: crash reports.

Reference sources:

- Decompiled vanilla scripts: `git clone --depth 1 https://codeberg.org/adamsmasher/cyberpunk.git`. Check method names and signatures there before wrapping anything.
- Equipment-EX's scripts are installed at `$GAME/r6/scripts/EquipmentEx/`.
- Layout files: `WolvenKit.CLI extract <archive> -o <dir> -r "<regex>"`, then `WolvenKit.CLI convert serialize <file>` to get JSON. Equipment-EX's wardrobe layout is `equipment_ex\gui\wardrobe.inkwidget` in `EquipmentEx.archive`. Library item handles are numbered per package, so resolve `HandleRefId`s within one library item.

## Layout

- `mod/`: the shippable files, mirroring the game folder (`r6/scripts/WardrobeTabs`, `archive/pc/mod/WardrobeTabs.archive`).
- `tools/`: the compile check and the card grid builder.
- `prototype/wardrobe-mockups/`: the HTML mockups layout B comes from.

## Architecture

### WardrobeTabs

Replaces the Equipment-EX wardrobe's slot accordion with layout B from `prototype/wardrobe-mockups`: a body column left of V (one group per body area with a tile per worn item and a + tile that switches the drawer to that area) and the item panel as a drawer: its own header in the panel's header column (title, search moved from Equipment-EX, area tabs, EQUIPPED ONLY), a slot sidebar left of the grid (inside the grid container, which is widened by `GridLeft()` with its contents moved right, so the right-anchored panel grows left), seven-column named cards (192 × 216 cells from the archive; the item display is scaled to 0.75 in `OnSpawned`) for the selected slot on a 50% black backdrop (colour grouping by item family exists but is switched off with `WardrobeTabsConfig.ColourGrouping()`; names were too varied to guess families), and an outfit bar over the grid's bottom edge (current look, OUTFITS / BACK). The outfits view replaces Equipment-EX's one-column outfit list (an `inkVirtualListController`, which cannot lay out columns) with the mod's own pooled cells (name, item count, a row of item icons resolved from each `OutfitPart`'s record and sorted by `GetOutfitSlots()` order) in a canvas inside the mod's own `inkScrollArea` (scrolled by `SetTranslation` on the mouse wheel's `OnRelative`, with a drawn scroll bar), placed in the outfit manager's root. A canvas added as a second child of Equipment-EX's `scroll_wrapper/scroll_area` never showed, probably because a scroll area shows one content child. Equipment-EX's `scroll_wrapper` stays, hidden, and its manager's `ShowSaveOutfitPopup` / `ShowDeleteOutfitPopup` are still used. The watcher polls `OutfitSystem.GetOutfits()` and the worn outfit while that view is open. Favourites are a `persistent` field added to `OutfitSystem` (`m_wtFavourites`), so they live in the savegame. Equipment-EX counts an outfit as worn only while the look's item hash matches it, so the mod keeps the outfit the look came from in another persistent field (`m_wtLinked`, set whenever the look matches an outfit, cleared by NO OUTFIT or deletion); after an edit the bar shows the slot change count with UPDATE (`SaveOutfit(name, true)`) and REVERT (`LoadOutfit`). B replaced an earlier slot sidebar (A). Two compiler constraints dictate its shape:

- `@wrapMethod` and `@addMethod` cannot target classes defined in scripts (any other mod's classes); only `@addField` can. Fully qualified names in annotations are rejected.
- Equipment-EX's grid classes are module-private, so the file declares `module EquipmentEx` to join that module.

So all behaviour is attached to the vanilla base class `inkPreviewGameController` and casts `this` to `WardrobeScreenController`. Filtering is done by replacing the grid's `ScriptableDataSource` contents with the selected slot's item entries (no slot header; its `IsCollapsed` is cleared so the items show), since Equipment-EX's `FilterItem` cannot be hooked. The mod keeps strong refs to the slot data, because the items' `Parent` is a weak ref. Equipment-EX rebuilds that source at moments no vanilla method observes, so a looping ink animation polls for it; untagged slot data (`m_wtTab == 0`) marks a fresh rebuild. The same tick polls the search text and the equipped filter (sidebar match counts) and `OutfitSystem` (equipped items), since Equipment-EX's own handlers cannot be wrapped either.

The body column is a canvas inserted as the first child of `wrapper` (`Reparent(wrapper, 0)`). Both `wrapper` canvases and `inventoryContainer` use `childOrder = Backward`, so the first child draws on top and gets input first; appended last, A's sidebar was hidden under the item panel and the preview took its clicks. Everything on the drawer is placed in Equipment-EX's own layout rather than at measured screen positions: the header is the first child of `vendorHeader` (Equipment-EX's header rows collapse), the outfit bar is the first child of `inventoryContainer` (moved to the outfit list's host in OUTFITS) and the backdrop its last. An overlay placed at measured coordinates ended up 67 units off once Equipment-EX's header changed height.

The search box (`m_searchInput`) and item-source button are reparented into the drawer header. The search box's `OnInput` callback to Equipment-EX's `OnSearchFieldInput` is unregistered: the watcher applies the text once it has been unchanged for `SearchSettleTicks()` ticks, through the data view's `SetSearchQuery`/`UpdateView`, and only refills the grid when the selected slot changes. Items' lower-cased names are cached on `InventoryGridItemData` (`m_wtSearchName`) for the per-slot match counts. `UIInventoryItem.GetName()` sometimes returns an unresolved `LocKey#...` string, so names go through `GetLocalizedText`. Some mods' names never resolve and show the raw key (e.g. Veegee's `casual_pt37_boots_black_name`); `CleanName` turns those into `casual pt37 boots (black)` so they group. Some mods' translated names are key-like too (`casual_pt37_boots_black`, no `_name`); any name without spaces and with two or more `_` is treated that way. Equipment-EX lists only the selected item source, so a worn item can be in no list at all; the mod reads its record from the player's slot (`TransactionSystem.GetItemInSlot`, Equipment-EX's preview copy), finds the real equipped item among the inventory, stash and wardrobe-store items, and inserts it first in its slot's `Children` (built like `PopulateInventoryGrid` does, with `UIInventoryItem.Make(player, slotID, ...)` so `IsEquipped` asks Equipment-EX). Only if no owned copy is equipped does the column fall back to the record's name and icon. families are built from those names when a slot is shown, and each build is logged (`WardrobeTabs` in CET's `gamelog.log`). Colour dots queue `WardrobeTabsVariantEvent`, handled by an `@addMethod` callback on `inkPreviewGameController` (whether ink delivers it to the screen is unverified in game).

Hover try-on: vanilla `InventoryItemDisplayController.OnDisplayHoverOver`/`OnDisplayHoverOut` are wrapped (the path Equipment-EX's tooltip takes; `OnEnter`/`OnLeave` registered on the card root showed no try-on in v15) and, for displays inside a `wardrobeCardItem` cell, record the hovered display on Equipment-EX's `ViewManager` scriptable system (`m_wtHoverCard`, plus `m_wtHoverDotItem` from colour dots; reached through Codeware's global `GetGameInstance()`), since card and screen share no other path. The watcher tick reads it: after `TryOnTicks()` on one item (9 ticks, 0.45 s since v28: 0.25 s pause plus a 0.2 s debounce; each try-on logs the measured pause) it puts that item on the preview puppet only (the `inkInventoryPuppetPreviewGameController` Equipment-EX records on `PaperdollHelper`, `GetPreview().GetGamePuppet()`; the screen's own `GetGamePuppet()` is null; slot cleared, then Equipment-EX's `EquipPuppetItem`); after `TryOffTicks()` with nothing hovered, or on OUTFITS, an equip, new data under the same card, or `OnUninitialize`, it restores with `EquipPuppetOutfit` (outfit active) or by clearing the tried slot (inactive). The bar shows `TRYING ON: <name>` meanwhile (confirmed working in game in v18).

Camera per area: `WardrobeTabsCamera` queues `gameuiPuppetPreview_SetCameraSetupEvent` on the same `PaperdollHelper.GetPreview()` controller Equipment-EX's wheel zoom uses (its wheel toggles setups Head/Default). Vanilla's 12 setups (`inventory_screen.inkwidget`'s `cameraController`) hold only two shots: 0–7 `UISlotPreview_FullBody` at zoom -1, 8–11 `UISlotPreview_UpperBody` at 1.85, so sending them per area (v19) moved nothing for ARMS/LEGS/FEET. The mod appends its own setups, one per area (`WardrobeTabsCameraSetups`, `m_wtFirstSetup`), with `CameraSlot`/`CameraZoom` per area. v20 and v21 appended them lazily on the first area click and V vanished on every area, whatever the aim point, so the bone-point theory below is unproven; v22 appends them in a wrap of the preview's `OnInitialize`, as the old PreviewZoom (which worked) did, and V stayed visible in game. v23: ARMS aims at `_FullBody`, FEET aims at `_Legs`, which in game sits at the ankles (1.6 showed one boot filling the view; v24 uses 2.2). v25 aimed HEAD at `_Head` and the camera went to V's feet: the bone-bound points do not follow V's bones in the wardrobe and resolve to V's origin plus their offset (`_Legs` = feet, 0.4 to the side, which pushed V right). v26: FEET aims at `_Head` (V's feet, centred) at 2.2, HEAD at `_UpperBody` at 1.45 (nothing higher works). The aim points available are the slots in `base\gameplay\gui\fullscreen\main_menu\prefabs\empty_room_inventory.ent` (`basegame_4_gamedata`): `UISlotPreview_Head` (Head bone), `_Chest` (Spine2), `_Legs` (Hips, X -0.4), `_UpperBody` (reference_joint Z 1.43), `_FullBody` (Z 1.05, X 0.2), `_Weapon`; none for the feet. Aimed at `_Legs`, V vanished from the wardrobe preview (v20, FEET at 1.7 and LEGS at 2.3); the bone-bound points (`_Head`, `_Chest`, `_Legs`, `_Weapon`) are taken as unusable there, so v21 aims only at `_UpperBody` (HEAD, BODY, ARMS) and `_FullBody` (LEGS; FEET keeps vanilla full body). A wrap of `OnSetCameraSetupEvent` passes the area's vanilla setup (`AreaCamera`: Head/OuterChest/Cyberware/Legs/Feet) for V's pose, as the old PreviewZoom did. `WardrobeTabsSelectArea` always sends it; `WardrobeTabsSelect` only when the slot is in another area than `m_wtCameraArea` (area + 1, 0 = full body). OUTFITS sends Default and keeps `m_wtCameraResume` for BACK. Equipment-EX resets to Default when the wardrobe closes. The room file (in `basegame_1_engine`, not `_4_gamedata`) also has unbound `UI_Preview` (Z 0.925) and `UIWardrobePreview` (X 0.2, Z 0.95); nothing sits between the feet and the hips, so v28 moves Equipment-EX's preview image (`wrapper/preview` from the wardrobe screen; v28 used Equipment-EX's menu-relative `wardrobe/wrapper/preview`, found nothing, and the lift never ran; a 2000 × 2000 `inkImage` anchored bottom centre, already shifted `PreviewShift()` sideways, which the lift keeps) down `FeetLift()` while the FEET setup is the last one applied (`m_wtSetup`, recorded in the `OnSetCameraSetupEvent` wrap, so the wheel zoom drops it), animated by `WardrobeTabsWatchLift`.

NEW tags: once per opening (`m_wtScanned`, in `WardrobeTabsCapture`) `WardrobeTabsScanNew` collects the record of every clothing item V owns (`WardrobeSystem.GetStoredItemIDs()`, `TransactionSystem.GetItemList` on the player and Equipment-EX's stash; `GetClothingRecord` filters), whatever the item source. Records not in the persistent `OutfitSystem.m_wtSeen` are added to it and, unless worn or on the first scan (`m_wtSeenReady`), to the persistent `m_wtNewItems`, mirrored as an `inkHashMap` on `ViewManager.m_wtNewSet` keyed by `TDBID.ToNumber` for the cards. A tag clears when the try-on pause fires on the card (even if the try-on is skipped) or when the item shows up as worn (`m_wtWorn` after a worn change). Cards draw a yellow NEW tag top left; `m_wtSlotNew` drives the yellow dot every button has (`m_wtButtonNews`, shown on area tabs and slot rows).

Mod packs: TweakDB keeps no source mod at runtime and nothing in game can read `r6/tweaks` (RedFileSystem is limited to its storage folder; ResRefs are hashes), so packs are detected in game by `WardrobeTabsPackOf`, once per record and cached on `ViewManager.m_wtPackList`: an item whose `DisplayName()` is a numeric `LocKey#…` (or empty) is base game; any other is a mod item, whose pack is its record ID's prefix up to the first `_` or `.` (`Items.yv_long_coat` → `yv`). `WardrobeTabsPackNames.reds` (generated by the dev-only `tools/build_pack_index.py` from the game's `r6/tweaks`, clothing records only, renamed through `tools/pack_names.txt`) names known prefixes; unknown ones show in capitals. Packs are appended in the order met (a choice is index + 2, so never reorder); the PACK list sorts its rows by name. Each wardrobe opening logs `Packs: …` with every detected pack and count. Items cache their pack on `InventoryGridItemData.m_wtPack`. The pack filter (`ViewManager.m_wtPackChoice`: 0 all, 1 base game, 2 + n) and pack-name search both go through `WardrobeTabsMatches`; since v29 the mod filters the grid itself in `WardrobeTabsApply` (only matching children are pushed) and no longer passes the query to Equipment-EX's `SetSearchQuery`, so every search refills the grid (`WardrobeTabsFilterChanged`). PACK is button `PackButton()` in the drawer header; its list is `PackRows()` pooled buttons in a canvas that is the grid container's first child. Redscript has no `continue`.

Settings: `WardrobeTabsSettings.reds` declares `WardrobeTabsSettings` with `ModSettings.*` runtime properties (jackhumbert's mod_settings writes saved values into every new instance; without the plugin the defaults apply, no `@if(ModuleExists)` needed). The screen takes a fresh copy in `WardrobeTabsBuild` (`m_wtSettings`), so changes apply on the next wardrobe opening. `hoverTryOn` off: the hover pause still clears NEW but starts no try-on. `areaCamera` off: `WardrobeTabsCamera` sends nothing (OUTFITS / BACK included), so the FEET lift never applies either.

Columns: the header's 4 5 6 7 buttons (`ColumnButton()`, after the pack rows) pick the card grid. The column count lives in the grid file (the virtual grid divides its width by the cell size, which script cannot change), so the archive carries one grid per count and `WardrobeTabsSpawnGrid` spawns `Root<n>`. The choice is the persistent `OutfitSystem.m_wtColumns` (0 = seven), read by `WardrobeTabsColumns()` at `WardrobeTabsInstallGrid` and switched live by `WardrobeTabsSetColumns`, which unbinds Equipment-EX's grid controller, spawns the new grid, rebinds Equipment-EX's classifier and data view to it and points `m_inventoryGridArea` / `m_inventoryGridController` at it. Card decorations scale by the cell's width over 192 (`WardrobeTabsCardScale`; text by half as much). The builder renumbers each copied item's `packageData.BufferId` in item order; WolvenKit refuses the JSON when copies repeat it (handle ids alone were not the cause).

Search clear: one X (`m_wtSearchClear`, `WardrobeTabsBuildSearchClear`) serves both search boxes, which share a place in the header; it is added after them (the header draws Forward, so it is on top), clears `WardrobeTabsActiveSearch()` (`m_searchInput` or `m_wtOutfitSearch`) and is shown per tick while that box holds text. The watchers then refill as for any search change.

The mod's clickable widgets (buttons, outfit cells, stars, group heads, tiles) act on `OnRelease` only if `OnPress` started on the same target (`m_wtPressed`, `WardrobeTabsPressedHere`): Enter confirms Equipment-EX's save-outfit popup on press, and its release probably hit SAVE OUTFIT under the cursor and reopened the popup (unconfirmed; v17 logs "Save outfit popup opened" per opening). One physical release arrives as several `OnRelease` events, one per input action, so a handler must test `IsAction(n"click")` before `WardrobeTabsPressedHere` (which clears the press): the outfit cells tested the press first and ignored every click from v17 to v36. Equipment-EX's delete key (`drop_item`) on an outfit cell skips the press check.

Card names: `VendorItemVirtualController.OnDataChanged` (vanilla) is wrapped; cells whose root is named `wardrobeCardItem` (from `tools/build_wardrobe_grid.py`) get an `inkText` under the item display, refreshed whenever the virtual grid recycles the cell.

In this setup a static function returning an array (expression-bodied or built with `ArrayPush`) came back empty at runtime, while the same code as an instance method worked; the cause is unknown, so keep such tables as instance methods. A related case: `ArraySize(screen.m_outfitSystem.GetUsedSlots())` written inline gave 1 while the same call stored in a local first gave 12. Store array results in a local before using them.

## Working conventions

- Wrap, never replace: Equipment-EX and Virtual Atelier hook the same screen, and `@replaceMethod` would break them.
- Change the UI from script at runtime. ArchiveXL cannot patch `.inkwidget` files and archive conflicts are first-file-wins, so shipping an edited vanilla layout would clash with other mods.
- Decompiled sources show fields as `m_name` for script classes; CET exposes the same fields without the `m_` prefix.
- State what has and has not been run in-game. A clean compile check says nothing about runtime behaviour.
- The user tests by hand, and replies can cross with installs. Before reading results, confirm from `scripting.log` and the redscript log that the session being reported actually loaded the current build.
